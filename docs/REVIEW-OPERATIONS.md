# FEKRA production acceptance and handover

The implementation register is [the 31 October review status](review-2026-11-04/STATUS.md). Local checks do not establish ownership or production delivery. An authorized FEKRA owner should complete the following with the deployer.

## Private CV storage

Create a PRIVATE applicant bucket distinct from public media. Inventory existing applications objects without downloading real applicant content into test systems. Copy them into the private bucket, compare sizes/checksums and authenticated downloads, and verify a synthetic object's anonymous public URL is denied. Test a short-lived signed URL and its expiry with scripts/check-private-storage.mjs. Set S3_PRIVATE_BUCKET only after the copy is verified. Retire public originals only after the approved backup/retention check. No destructive storage migration was performed here.

The application guard refuses new uploads while public media lacks a separate private bucket. This is a release prerequisite. Bucket privacy and legacy-object removal require platform access; a signed URL alone does not protect an object in a public bucket.

## Release and rollback

1. Preserve a dated, secured production database/storage backup and record its checksum. Restore it to an isolated environment; do not put applicant data in ordinary development fixtures.
2. Verify environment separation by comparing database project identity and least-privilege roles, without exporting connection strings into the report. Local development must not reuse production credentials. The QA runners refuse a remote database.
3. Run the committed migrations and build on the reviewed commit. The new newsletter migration also adds indexes generated by the Payload update. Record the deployed SHA and sanitized environment fingerprint.
4. Verify CV access, all form types and languages with controlled addresses. Match each database record, attachment, provider ID and real mailbox receipt. Clean only identified synthetic records.
5. Verify the full current sitemap from two regions with bounded concurrency and raw status/timing/cache output. Run mobile PSI on key templates; approve p50/p95 and LCP targets before changing hosting infrastructure.
6. Configure and test uptime alerts to FEKRA. Require the Quality job for production-branch merges. A health workflow file is supplied but has not been activated remotely.
7. Record the previous deployment and database compatibility before promotion. If rollback is needed, restore the application version compatible with the schema and use the tested backup procedure. Do not run destructive down migrations against live submissions without an approved recovery plan.

Record owner-approved RPO, RTO and warranty/bug response terms. No response-time or legal obligations were invented in this checkout.
